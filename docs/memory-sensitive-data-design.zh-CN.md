# 记忆敏感信息处理设计

## 1. 背景与目标

当前记忆系统包含自动记忆、后台提取、AutoDream 归并、SessionMemory 以及查询时召回。任何单点提示词约束都无法覆盖手工修改、历史遗留文件或模型未遵循指令的情况，因此敏感信息处理必须成为贯穿整个数据生命周期的确定性策略。

本方案的目标是：

- 敏感内容默认不能以明文写入持久记忆。
- 历史或人工写入的敏感内容不能在召回时进入模型上下文。
- 允许不同安全等级的环境选择“脱敏保留”或“整条拒绝”。
- 不改变现有记忆文件格式，不引入新的运行时依赖。
- 配置内容本身不进入提示词、日志或遥测。

## 2. 范围

覆盖以下链路：

```text
会话消息
   │
   ├─ 自动提取 / SessionMemory / AutoDream
   │              │
   │         写入前策略检查
   │              │
   └──────────> 记忆文件
                  │
             索引扫描与候选选择
                  │
             正文读取与再次脱敏
                  │
               模型上下文
```

不在本阶段处理：

- 原始会话日志和第三方服务自身的数据留存。
- 通用命名实体识别，例如自动判断所有姓名、地址或电话号码。
- 已存在记忆文件的离线批量清洗；运行时召回仍会进行兜底脱敏。

## 3. 策略模型

### 3.1 敏感内容来源

策略同时处理两类内容：

1. 内置高置信规则：私钥块、常见 API Token 前缀、带明确标签的密码、密钥和访问令牌。
2. 用户自定义词组：通过 `CLAUDE_CODE_MEMORY_SENSITIVE_TERMS` 配置，使用逗号或换行分隔。

自定义词组按字面量、大小写不敏感匹配，不允许配置正则表达式。这样可以避免错误表达式、灾难性回溯及配置注入风险。

### 3.2 处理模式

由 `CLAUDE_CODE_MEMORY_SENSITIVE_ACTION` 控制：

| 模式 | 写入行为 | 索引行为 | 召回正文行为 | 适用场景 |
| --- | --- | --- | --- | --- |
| `redact` | 将命中值替换为 `[REDACTED]` | 描述脱敏后参与选择 | 再次脱敏 | 默认；尽量保留非敏感上下文 |
| `exclude` | 拒绝包含敏感内容的生成写入 | 描述命中的文件不参与自动召回 | 对漏网内容仍脱敏 | 强合规或宁可丢失记忆的环境 |

未知或未配置的模式回退为 `redact`。

## 4. 分层防御

### 4.1 提取阶段

自动提取提示词和主记忆提示词明确要求不保存凭据、私钥、Token、密码及用户指定的敏感词。这一层减少模型生成不合规内容的概率，但不作为唯一安全边界。

### 4.2 生成和持久化阶段

`Write` 的 `content` 与 `Edit` 的 `new_string` 在文件工具执行前经过统一策略：

- `redact`：替换后将新的工具输入交给文件工具。
- `exclude`：权限回调直接拒绝本次写入。

文件路径、`old_string` 等非持久化定位字段不修改，避免破坏 Edit 的匹配行为。自动记忆、AutoDream 和 SessionMemory 共享同一策略函数。

### 4.3 索引与相关性选择阶段

扫描记忆文件 frontmatter 时先处理 `description`：

- `redact` 模式只向相关性选择器提供脱敏描述。
- `exclude` 模式不把描述命中的文件加入候选列表。

用户查询也会先脱敏再发送给相关性选择器，避免自定义敏感词因相关性判断而被发送到额外的模型请求。

### 4.4 召回注入阶段

被选中的记忆正文在组成 `relevant_memories` 附件前再次脱敏。这是最终兜底，可覆盖：

- 功能上线前形成的历史记忆。
- 用户手工编辑的记忆。
- 描述无敏感词但正文含敏感词的文件。
- 上游提示词或写入拦截发生异常的情况。

SessionMemory 在读取并用于压缩续接前采用同样的正文脱敏。

## 5. 安全与隐私约束

- 自定义词表只在进程内读取，不将具体词值写入提示词或遥测；提示词只包含词条数量。
- 内置规则保持高置信和窄范围，降低误杀。
- 不记录命中的原文，仅保留是否命中和数量供内部函数判断。
- 多层检查采用相同实现，避免提取与召回的规则漂移。
- `exclude` 不能撤销模型已在原会话中看到的信息，其保护边界是持久记忆和后续召回。

## 6. 兼容性与性能

- 未配置环境变量时仍启用内置凭据规则，默认行为为脱敏。
- 记忆 Markdown 格式和 frontmatter 格式保持不变。
- 匹配只发生在候选描述、写入字段和最终读取正文上，没有目录级全文件重复扫描。
- 自定义词较多时复杂度近似为 `文本长度 × 规则数量`；如未来需要上千词规模，可替换为 Aho-Corasick，同时保持当前策略接口不变。

## 7. 测试策略

单元测试覆盖：

- 自定义中英文词组及大小写不敏感匹配。
- API Key、GitHub Token 等内置凭据模式。
- Write/Edit 字段过滤且不修改文件路径。
- 默认模式及 `exclude` 模式解析。

发布前还应进行集成验证：分别触发自动提取、AutoDream、SessionMemory 和相关记忆召回，确认磁盘文件及模型附件均不含测试敏感值。

## 8. 后续演进

- 将环境变量配置接入正式 Settings UI，并支持用户级、项目级作用域。
- 增加只记录计数、不记录内容的命中遥测。
- 提供显式的历史记忆扫描与迁移命令。
- 在有明确合规需求时增加可选的邮箱、手机号或证件号规则包。
